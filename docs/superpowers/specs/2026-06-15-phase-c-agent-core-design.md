# Phase C — Agent Core: Design

> Status: approved 2026-06-15. Implements Project_plan.md Phase C (Days 5–7).
> Branch: `feat/phase-c-agent-core`.

## Goal

Wire the four-agent pipeline (Planner → Retriever → Analyst → Critic) over the
existing SQLite store so that:

- **Q&A path** answers a natural-language requirement query with inline citations.
- **Audit path** sweeps the corpus for cross-document contradictions and finds
  **≥12/15** seeded cases, with the LLM Critic rejecting false positives.

Everything must be observable (LangFuse) and the contradiction-recall number must
be gate-able in CI **without API keys**.

## Decisions locked in brainstorming

1. **Retrieval is deterministic lexical (BM25) over SQLite now.** The dense/Qdrant
   arm is deferred to Phase E (Benchmark), which already sweeps dense vs hybrid vs
   rerank. The tool keeps the name `hybrid_search` (per the locked architecture and
   README), but its current implementation is lexical-only — flagged honestly in
   code and README.
2. **LLM access goes through an `llm/` provider abstraction** (Anthropic primary,
   OpenAI fallback). Tests swap in PydanticAI `TestModel`/`FunctionModel` via
   `agent.override(...)`, so the full agent graph runs deterministically with zero
   keys. Real provider calls happen only when keys are present (local, nightly).
3. **Contradiction detection is hybrid — deterministic where a signal exists, LLM
   where the conflict is semantic.** Tracing the 15 seeded cases shows a hard
   ceiling of 11/15 for purely deterministic rules: `numeric_mismatch` (C01–C05)
   and `superseded_reference` (C11–C15) have clean signals, but four of the five
   `incompatible_constraint` cases (C07–C10) are prose/semantic conflicts with no
   rule signal — and the Critic only *filters*, so it can't add recall back. So:
   - **Deterministic detectors** (no LLM, **gate-able in CI without keys**):
     `numeric_mismatch` = two requirements share a parameter name with differing
     numeric values; `superseded_reference` = a cross-ref whose target has
     `status=superseded`. Catches the numeric + superseded classes (10 cases, plus
     C06 which also shares a parameter) with clean precision (near-misses N01–N03
     are correctly not flagged).
   - **LLM comparator** for the `incompatible_constraint` class: candidate pairs are
     generated by cross-document lexical neighbours (reusing the BM25 retriever),
     then an LLM judges whether the pair conflicts. Bounded by top-k neighbours and
     a `max_audit_pairs` budget. Catches C07–C10.
   - **Critic** verifies every surfaced candidate (deterministic or LLM) against its
     quoted sources and rejects false positives — the "before vs after Critic"
     precision metric.

   The eval reports **two recall numbers**: deterministic recall (gated, no keys)
   and full recall (with LLM, nightly/local). Target ≥12/15 is met by the full run.

   **Integrity rule:** neither the deterministic comparator nor the LLM comparator
   reads `evals/contradictions.json`. Both operate only on real chunk/entity data.
   The eval compares their independent output against ground truth.

## Modules (under `src/requirements_audit/`)

- **`config.py`** — `pydantic-settings` `Settings`: LLM provider/model (pinned),
  fallback provider, budgets (`max_agent_steps`, `max_tokens_per_run`,
  `max_usd_per_run`), `sqlite_path`. Importable without any keys set.
- **`llm/provider.py`** — `build_model(settings)` → PydanticAI model with
  Anthropic→OpenAI fallback (`FallbackModel`). No network at import time.
- **`retrieval/lexical.py`** — `search(store, query, k) -> list[ScoredChunk]`:
  BM25 ranking over `chunks`. Deterministic. Structured so a dense arm fuses in
  at Phase E.
- **`tools/`** — three typed, deterministic tools (the "Retriever" role; no extra
  LLM call): `hybrid_search(query, k)`, `get_section(doc_id, section)`,
  `find_refs(req_id)`.
- **`agents/audit.py`** — the candidate-generation layer. *Deterministic* detectors
  for `numeric_mismatch` (shared parameter, differing value) and
  `superseded_reference` (ref → superseded target) → `CandidateContradiction[]`;
  this is the gate-able, LLM-free recall stage. Plus the *LLM comparator* for the
  `incompatible_constraint` class over cross-document lexical-neighbour pairs
  (budget-bounded). Both feed the Critic.
- **`agents/planner.py`** — PydanticAI agent: routes `qa` vs `audit`, decomposes
  complex queries → typed `Plan`.
- **`agents/analyst.py`** — Q&A: PydanticAI agent with the three tools; drafts an
  answer with inline citations → typed `Answer`.
- **`agents/critic.py`** — LLM agent: verifies a candidate/answer against quoted
  sources, rejects FPs, emits confidence → `CriticVerdict`.
- **`orchestrator.py`** — typed `RunState` with budget/loop-cap enforcement
  (`BudgetExceeded`); entrypoints `answer_query(...)` and `run_audit(...)`.
- **`tracing.py`** — LangFuse wrapper; **no-op when keys absent**.

## New typed models (in `models.py`)

- `Citation(doc_id, requirement_id, quote)`
- `Answer(question, text, citations)`
- `Plan(route, subqueries)`
- `CandidateContradiction(...)` — mirrors `Contradiction` so eval comparison is
  mechanical.
- `CriticVerdict(is_conflict, confidence, rationale)`
- `Finding(candidate, verdict, human_status)` — `human_status` is the
  human-review gate (`pending` | `accepted` | `dismissed`, default `pending`).

## Store additions (`store.py`)

- `get_section(doc_id, section) -> list[Chunk]`
- `refs_from(req_id)` / `refs_to(req_id) -> list[CrossRef]`
- `entities_by_name(name) -> list[Entity]` (for pairing)
- `chunk(req_id) -> Chunk | None`

## CLI

Implement the `query` and `audit` stubs:

- `query "<question>"` → prints the answer with citations.
- `audit` → prints a findings table (pair, conflict type, confidence, status).

## Tests (deterministic, CI-gated)

- **Deterministic audit recall** on the numeric + superseded classes, computed
  with **no LLM** (gate-able): all 10 of those true conflicts found, near-misses
  N01–N03 not flagged. The full ≥12/15 (incl. incompatible_constraint) is exercised
  with a `FunctionModel` standing in for the LLM comparator.
- **Retrieval smoke** on hand-picked questions (sane top-k).
- **Agent wiring** via `TestModel`/`FunctionModel`: Planner routing, Analyst
  citation + tool-call shape, Critic verdict schema, budget caps enforced.
- **CLI** `query`/`audit` run under a test-model override.

## Out of scope for Phase C (unchanged)

Qdrant/embeddings (Phase E), Ragas/judge calibration (Phase D), FastAPI/SSE
(Phase F), Streamlit UI (Phase G).
